## Evidence lifecycle

Write new observations with [template.md](template.md). Record the tested code,
fixture/model, method, failures and limits; distinguish a new result from a
repeated historical statement. Accepted contracts, not mappings, govern behavior.
Every mapping carries an `Observed:` line (the validator checks it). Keep a paid
or frozen campaign as a compact receipts table: owner approval, calls, spend,
frozen input hashes and outcome, plus every failure. Do not keep a long narrative
ledger or a status tracker in a mapping: status lives only in the
[roadmap](../roadmap/epics/index.md), and a mapping above 5,000 words draws a
validator warning, so link the full text at a pinned Git revision instead.

Superseded studies, duplicate milestone reports and rejected mockup reviews were

exact files at [checkpoint f2673d7](https://github.com/MikeK184/Recollect/tree/f2673d71c4b63b536d41b3143eb39c207955b201/docs/mappings).
