# Backup and recovery interface research

Observed: 2026-09-26
Confidence: verified against primary sources, owned SFTP/PostgreSQL/Neo4j runtime,
fresh named installations and desktop product paths. This is local acceptance,
not external deployment or a production capacity claim.

The product Compose file selects PostgreSQL 17/pgvector. Context7 initially
returned PostgreSQL 16 examples; that mismatch was corrected to
`/websites/postgresql_17` and the official
[pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html) and
[pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html) pages. A logical
dump is consistent within PostgreSQL, not across independently changing artifact
files. Custom-format archives preserve database definitions/data for restoration;
cluster roles are separate. The existing installation already creates the admin
and application roles. A quiesced app plus dump/files is the selected first-usable
consistency boundary, without claiming WAL replication or universal recovery loss.

The official [age repository](https://github.com/FiloSottile/age) and
[v1.3.2 release](https://github.com/FiloSottile/age/releases/tag/v1.3.2) provide an
existing encryption CLI and downloadable Mac/Linux binaries. Context7
`/filosottile/age` confirms recipient/identity-file operation and authenticated
decryption failure tests. Restore must finish authentication before any SQL/import;
streamed plaintext is not treated as a verified archive. The age man-page URL
`https://filippo.io/age/age.1` returned a web-tool internal error; the repository's
README, `doc/age.1.html` and CLI tests supply the verified interface instead.
Neither age nor restic was installed on this Mac at the time of inspection.
The delivered repository-local tooling preserves global configuration.

The repository-local age 1.3.2 installer now provides the official Mac binary.
Actual encryption/decryption, wrong-key and corrupted-final-chunk checks pass;
failed plaintext is removed before extraction or destination I/O. The isolated
OpenSSH SFTP fixture accepts its generated key and pinned host key. A Rust
privacy request remains unacknowledged with an untrusted host, denies erased
content locally and completes after trust repair with one encrypted remote entry;
startup retry over that same remote filename succeeded. Evidence:
`.cache/recovery-age-proof-20260926.json`,
`.cache/recovery-mirror-proof-20260926.log` (one integration test, latest 4.02 seconds),
and `.cache/recovery-archive-proof-20260926.log` (four tests).
At this proof's start the normal installation remained at migration 024, while
the isolated recovery image and restored installations used migration 025. It
was subsequently upgraded to 025 with seven Brains, 33 model requests and the
existing profiles/grants preserved (`.cache/recovery-normal-proof/`). The

The [OpenSSH SFTP manual](https://man.openbsd.org/sftp) documents noninteractive
batch operations, explicit identities/host configuration, failure stopping and
supported remote flush behavior. The operator adapter uses fixed owned paths,
private batch inputs and staged upload/rename; no remote shell implementation or
home SSH defaults are needed. `/usr/bin/sftp` is present locally. The owned endpoint
drill now proves real transport, unknown-host refusal and interrupted publication.

Existing Rust `privacy_journal` initialization/export/reconcile and analytical
ownership journals already enforce installation identities and older-state
barriers. Migration 024 extends those opaque fences to managed call/outbox copies.
The new recovery adapter reuses these authorities. Remote-enabled erasure completion
must await the additional encrypted mirror acknowledgement; a periodic data backup
alone cannot cover acknowledged erasures made afterward.

Atlas `recoverable-background-work` separates input durability from fair bounded
processing, while `rejected-value-tombstone` distinguishes value rejection from
record deletion and requires every later write to consult the rule. The current
memory contract and database retain rules independently of source IDs. Restoration
must preserve those checkpoint rules and prove later re-entry is still blocked;
an empty fresh graph or a successful decryption is insufficient evidence.

The ordinary-data recovery point deliberately remains distinct from the current
erasure ledger. Changes made after the chosen canonical checkpoint are not
invented or claimed recovered. This is the disclosed backup recovery-point limit,
not a promise of zero-loss replication. The
[execution pack](../roadmap/execution/archive/operations-recovery-drills.md) records
the required positive/negative product-path proof and closeout.

PostgreSQL's [sequence documentation](https://www.postgresql.org/docs/17/functions-sequence.html)
and a follow-up Context7 query confirm that rollback and conflict handling may
skip identity sequence values. Recovery therefore compares actual opaque request
identities using an independent inventory or predecessor links, rather than
assuming every integer must exist. The archive tests accept a legitimate 1/3
sequence and reject a missing listed entry, an older checkpoint journal and a
different installation marker. Remote chain and analytical mirror proof now
passes against the real SFTP endpoint: the Rust deletion test fetches the
independent encrypted journal, and
`.cache/recovery-analytics-mirror-proof-20260926.log` proves an actual GDS analysis
mirrors and recovers its ownership/closed entry (one test, 5.98 seconds). Missing
predecessor detection is covered by the archive tests; remote deletion failure
and full installation recovery also pass in the completed drill below.

The schema compatibility and ordered identity integration test passes in
`.cache/recovery-migrations-proof-20260926.log` (0.85 seconds). It observes a real
concurrent insert waiting before identity allocation, then a rolled-back numeric
gap; migration 025 supplies the before-statement transaction lock. The held
recovery test initially found an incorrect combined-graph field in the new SQL;
it now uses the existing input snapshot array. The corrected test passes queued
and running call fencing, immutable unknown outcomes, model accounting and
late-receipt reconciliation. The subsequent endpoint-relocation extension also
passes (one test, 0.97 seconds in `.cache/recovery-fencing-proof-20260926.log`),
preserving the receipt while rejecting its old owner. Earlier regression proof
is in `.cache/recovery-runtime-20260926.log` (25 passes and the subsequently fixed
SQL failure), so that initial run is not reported as a clean suite.

The Python scripts suite passes seven tests with one explicitly unselected Caddy
fixture skipped in `.cache/recovery-python-proof-20260926.log`; this includes real
native TLS verification. The final archive/crypto run passes four cases in
`.cache/recovery-archive-final-20260926.log`; the mirror configuration consistency

The OpenSSH endpoint is an owned local container with generated pinned keys;

Original checkpoint erasure occurred afterward. Current independent journals kept
the capture and derived claim excluded after every restore, and replay returned
`removed`. Corrected history, rejection rules, independent captured/managed recall,
reader/private-Brain boundaries and direct retained source reads survived. A fresh
Neo4j rebuilt the eligible knowledge view and the repository's two vertices/one
relationship. The manually reviewed source also supported a rejected assertion;
its raw fragment correctly remained filtered, so it is not the independent recall
control. The separate retained capture and managed observation supply that control.

The real managed connector wrote one external effect then disconnected. Its call
stayed uncertain through recovery and receipt-only reconciliation; the effect
count remained one. Only the crash-state model request was seeded (100 reserved
tokens); restore preserved `uncertain:100` and made no paid model request. Focused
Rust tests separately exercise queued/running fencing and later receipts. This
does not claim the synthetic fixture is a provider billing measurement.

The original interruption drill exposed a helper-start race in its own cleanup.
The final drill waits for the helper to run before killing the operator and leaves
it for product resume to retire. Compose's documented
[`run --label`](https://docs.docker.com/reference/cli/docker/compose/run/) and
project/service labels scope that retirement. A unique
[`PGAPPNAME`](https://www.postgresql.org/docs/17/libpq-envars.html) scopes the import
session; PostgreSQL's waiting
[`pg_terminate_backend`](https://www.postgresql.org/docs/17/functions-admin.html#FUNCTIONS-ADMIN-SIGNAL)
confirms rollback before resume. Context7 `/docker/docs` and the installed Compose
CLI confirmed these interfaces. The session-termination control is a tagged open
transaction, not a claim that another full dump was imported in that control.
