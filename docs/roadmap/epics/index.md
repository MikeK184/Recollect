## Implementation Entry and Sequence

Implementation started with `platform-bootstrap` in
[Product Platform and Access](product-platform.md). Its accepted ADR, contract and
archived pack record delivery. All original stages below are complete. The final
`operations-integrated-evaluations` pack is archived; the subsequent desktop
assignment adds the nine scoped packs above. External deployment remains excluded.

| Stage | Capability milestone and handoff |
| --- | --- |
| 1 | Runnable Rust/React/storage foundation with local owner and Brain isolation; add durable work, team identity and paired devices |
| 2 | Collections, workspace scope and exact repository publication supply evidence/manifests for claims, time, review and correction |
| 3 | Retention/erasure unlock automatic session capture; exact retrieval, model-approved semantic work and scoped graph projections can progress from their named predecessors |
| 4 | Complete graph linking/analytics/exploration and retrieval fusion/UI; coordinate approved MCPs, Vault and private runners and expose shared memory/workspace handlers |
| 5 | Verify full personal/team deployment, recovery and integrated quality/concurrency behavior across all required features |

This is a dependency order, not a requirement to finish every slice in an epic
before beginning another. Each epic's Slice Dependencies table names the actual
predecessors. For example, evidence collection/publication precedes memory rules,
while automatic session capture waits for memory retention/erasure. Graph fusion
waits for graph path support; graph computation does not wait for retrieval UI.
MCP catalogue/runtime work can progress once platform and workspace scope exist.

All seven product epics belong to the first usable scope. Graph analytics, Vault
integration, private runners and review are not optional later releases merely
because they occur after the initial runnable foundation. Security, provenance,
audit, correction and focused tests accompany the owning feature slices; final
integration proof does not defer those obligations.
Vault use is optional for each connection; delivering the adapter does not require
an operator to enable it or migrate environment/OS-store/anonymous connections.

## Seven-Capability Ownership

| Required capability | Primary owner and downstream proof |
| --- | --- |
| Rejected-value tombstone | Memory review/corrections; evidence re-entry, retrieval and graph rebuild consume the durable rules |
| Explicit trust state | Memory claims/review; retrieval, graph reports and UI enforce and display the separate state dimensions |
| Bi-temporal validity | Memory claims/time; evidence manifests and historical retrieval preserve distinct revision and time questions |
| Scope enforced | Platform access plus workspace task scope; every epic tests its API/worker/cache/runner path with positive controls |
| Mutation audit | Platform auditable commands/durable work; memory mutations and all producers use the same transactional boundary |
| Human review | Memory lifecycle owns optional review/conflict overrides; normal maintenance is autonomous and retrieval/graph views link to the same authority |
| Negative evaluations | Every feature slice owns negative/positive tests; operational readiness assembles the integrated seven-capability proof |

Knowledge collections, repository memories, runbooks and handovers are owned by
evidence/memory epics; knowledge and repository graphs by graph intelligence;
Brain/environment MCP profiles and credential delivery by MCP coordination.
User-visible workflows belong with their capabilities rather than an isolated
frontend epic. The [foundation research mapping](../../mappings/atlas-foundation-decisions-2026-09-13.md)
records the source evidence and remaining detailed contract boundaries.
