# Scoped project brief and continuation

Status: shipped
Owning epic: `docs/roadmap/epics/hybrid-retrieval.md`
Work type: product

## Summary

- Goal: Supply compact stable scoped context and authenticated current session continuation within normal plugin recall.
- Non-goals: Universal semantic merging, personal inference, automatic command execution.
- Delivery shape: Recall DTO/packing, canonical context roles, migration 040 continuation lineage, plugin integration and controlled proofs.

## Scope

- In scope: Deterministic scoped decisions/conventions/constraints, optional typed continuation hints, exact authenticated task/predecessor selection, shared query/context budgets, native coverage framing and ordinary eligibility gates.
- Out of scope: New model calls, larger host context/time allowances, a parallel brief store, recency-based session guessing and paid quality claims from fixtures.
- Blockers: None for local acceptance; deployment remains separate.

## Surface and Interface Changes

- Interfaces: Optional project brief, typed continuation hints, delivery sections and canonical descriptive context roles.
- Storage: Immutable same-owner closed-task continuation lineage in migration 040; no brief cache or second memory authority.
- Ownership: Canonical retrieval assembles; native plugin delivers; the memory lifecycle owns source/digest support.

## Data and Authority

- Inputs: Current supported exact-scope attributed claims/digests with ordinary validity/manifest/collection/ACL gates.
- Authority: Immutable authenticated operation scope, same-owner/device closed-task lineage, standing Brain permissions and existing human decisions.
- Blind spots: Bounded context is incomplete; a declared convention or continuation supplies no operational verification.
- Budget: Three brief items, 1536 serialized bytes; shared result/byte limit, query priority and six-record/8192-byte/eight-second plugin cap.

## States and Edge Cases

- Loading: Resolve ordinary ranked recall and deterministic supported context in one request budget.
- Empty: Non-query context is labelled scoped-only; no matching supported context supplies empty coverage.
- Error: Rich retrieval uses the existing lexical fallback within the same eight-second deadline.
- Blocked: Human rules, conflict, support/coverage lag and logical deadlines withhold affected items.
- No-access: Spoofed or foreign task/device/binding hints are forbidden; model context grants no permission.
- Duplicate or replay: Deduplicate identity at whole-record admission; stable context pays no extra call.
- Stale data: Shared support, epoch, erasure and exact generation/revision association invalidate continuation.
- Reconciliation divergence: Multiple compatible episodes omit continuation with bounded coverage; never choose newest.

## Integrations and Runtime Inputs

- Providers: Existing ordinary rich recall only; no new model call for brief or continuation.
- Environment: Installed plugin task/operation and canonical Brain selection/manifest/collection.
- Secrets: Existing payload screening; no source-code or credential investigation is required.
- Failure handling: Rich timeout and lexical fallback preserve coding; fully escaped hook output stays within 8192 bytes.

## Tests and Acceptance

- Automated: Whole-record budgets, operational/temporal gates, deterministic brief, no extra charge, ambiguity, exact scope/manifest/collection, same task/predecessor and cross-user/device/spoof rejection.
- Manual: Independent source review and native resume proof without scope guesses.
- Acceptance: Supported useful context and honest coverage within unchanged count/byte/time limits, preserving corrected/erased/expired and protected controls.
